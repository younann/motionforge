# MotionForge Studio: design

## Intent
A publishable Claude Code plugin. A user runs `/motionforge:open` in Claude Code, a local browser studio opens, and they make short animated ad videos (max 30s) from a prompt, optionally with an attached image. The user's own installed Claude Code CLI does the generation (no API key, no cloud backend). The result lands on a timeline where the user edits by hand, then exports a high-quality MP4 with music and sound effects.

The most important goal: **high-quality end results.**

## Goals (first release)
- Prompt → animated video, up to 30s. Formats 9:16, 1:1, 16:9.
- Image input, two uses: **Use in scene** (the image is a layer in a generated ad) and **Rebuild as animation** (Claude reads a static design and recreates it as live, editable layers).
- Two studio modes over one project: **Simple** (prompt-first, Canva-like) and **Editor** (CapCut-like: chat left, preview center, inspector right, multi-track timeline bottom).
- Timeline editing: trim, reorder, split, duplicate, delete, scene duration, per-scene crop/zoom, transitions, output aspect.
- Re-prompt one selected scene without touching the others.
- Audio: bundled CC0 music and SFX, user-uploaded music/voiceover, separate music + SFX tracks with trim, volume, fades, mute. Claude picks music and places SFX.
- Export MP4: 1080p default, 4K option; 30fps default, 60fps option; H.264 + AAC.

## Non-goals (this release)
- Pro mode (layers × keyframes editor). Comes next; the data model already supports it.
- Generated voiceover (TTS). Upload only.
- Automatic background removal from photos.
- Blender, Remotion (license), Motion Canvas.

## Anti-goals
- Generic, template-looking output.
- Running arbitrary generated code with system access.
- A heavy install: users need only Node 20+, Claude Code, Chrome/Chromium and ffmpeg.

## How it works (decided)
- **Composition model (`comp.json`)**: output size/fps, ordered `scenes` (video track) each with duration, trim, crop, transition and `layers`; `audio` clips (music/sfx/voice). Layers are `text`, `image`, `shape`, `background`, `code`. Each layer has static props, `enter`/`exit` presets from a curated motion library, and optional per-property keyframes with easing.
- **Engine**: one deterministic renderer, a pure function of time, used for both preview and export. No CSS animations; every frame is computed. Code layers draw on a canvas via `draw(ctx, t, w, h)`.
- **Isolation**: the stage renders in a sandboxed iframe (`allow-scripts`, no same-origin) so generated code can't reach the studio or its token.
- **Generation**: server spawns `claude -p` in the project folder with only Read/Write/Edit/Glob tools, `acceptEdits` permission mode, no MCP, no user plugins/hooks, and an appended system prompt documenting the comp schema and motion library. Claude writes `comp.json`; the server validates and normalizes it, and feeds errors back once for a repair.
- **Export**: server launches headless Chrome over the DevTools protocol (Node's built-in WebSocket, zero npm deps), steps frames, pipes screenshots to ffmpeg, mixes audio with ffmpeg filters.
- **UI**: no build step. Preact + htm vendored as one ES module. Dark studio theme.
- **Assets**: bundled OFL fonts; CC0 music/SFX generated by a script in the repo (we own them, so they ship as CC0).
